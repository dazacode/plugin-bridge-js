# plugin-bridge-js

**A compatibility and translation toolkit for adapting foreign plugin ecosystems
into a portable JavaScript runtime for web and cross-platform clients.**

Six plugin ecosystems exist for the same job and none of them run in a browser.
This turns their extensions into one portable JavaScript plugin, running in a
sealed sandbox behind a declared host port — so the same converted plugin runs
in a browser tab, a desktop shell, a phone, or a terminal.

It is a **translator**, not an emulator. Nothing here pretends to be Android.

```
foreign extension ──► adapter ──► front-end ──► emit ──► JS bundle
                                                          │
                                            sealed sandbox ┴─► host port ─► any surface
```

## What it is for

- **Translating** a foreign extension into JavaScript, statically, with no
  device runtime and no bytecode interpreter.
- **Measuring** whether the result actually works, against the real thing, and
  saying precisely what stopped it when it does not.
- **Refusing**, loudly, when it cannot translate something — see below.

## The rule everything else follows from

> **A conservative refusal is better than silent wrong behaviour.**

A half-translated extension installs, searches, and shows the wrong episodes.
That is worse than one that will not install, because nobody can see it. So the
translator names every construct it cannot read, with the file, member and line,
and refuses the member rather than emitting something approximate. The refusals
are the work queue; the scoreboard ranks them.

This is not a slogan. Most of the bugs this project has found were _conversions
that reported success_: a `+=` on a list that rebound instead of appending, a
reified type parameter emitted as the string `"R"`, a `by lazy` that ran at
construction. Each one produced a plugin that installed and did the wrong thing.

## Install

```sh
bun install
```

Requires [bun](https://bun.sh). Node 22+ works for everything except the runtime
generator, which is pinned to one bun version on purpose — bundler identifier
renaming is not stable across minors, and the generated bytes must be.

## Use

```sh
plugin-bridge inspect ./path/to/extension      # what it declares, what we refuse
plugin-bridge convert ./path/to/extension      # translate it, write the bundle
plugin-bridge check   ./path/to/extension      # translate and report
plugin-bridge validate ./bundle.zip            # read a bundle back, check digests
plugin-bridge catalogue <index-url>            # score a whole repository
```

Ecosystem-scoped forms are accepted where a format cannot be detected:

```sh
plugin-bridge aniyomi inspect ./path/to/extension
```

**No index URL ships with this repository.** `catalogue` takes one as an
argument, every time. See [`docs/security.md`](docs/security.md) for why.

## Layout

| Package             | What is in it                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `packages/core`     | The Kotlin front-end — grammar, subset, emitter, pipeline — and the format-agnostic conversion machinery           |
| `packages/runtime`  | The shims a converted bundle is built from: the Kotlin standard library, a jsoup-shaped DOM, the ecosystem drivers |
| `packages/adapters` | One adapter per ecosystem: `aniyomi`, `mangayomi`, `cloudstream`, `sora`, `hayase`, `lnreader`                     |
| `packages/host`     | The host port, the sealed sandbox, a headless isolate, the network relay, the scoreboard                           |
| `packages/cli`      | `plugin-bridge`                                                                                                    |

## Status

Honest numbers, from one 254-listing repository:

|                                                            |        |
| ---------------------------------------------------------- | ------ |
| Listings that convert, load and run                        | **60** |
| Of those, live and reachable                               | **27** |
| Of those, completing `search → episodes → resolve → fetch` | **5**  |

The gap is mostly **not** this software: 33 of the 60 never answer at all — 20
behind an anti-bot challenge, 6 whose host does not resolve, 6 whose endpoint is
gone, 1 serving no https. Of the rest, roughly half have simply changed their
markup since the extension was written.

`docs/adr/0005-network-boundaries.md` decides what this will and will not
acquire to close that gap, with the count each capability is worth.

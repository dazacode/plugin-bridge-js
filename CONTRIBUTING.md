# Contributing

## The standards this project holds

They are unusual, and they are the reason it is worth contributing to.

1. **A conservative refusal beats silent wrong behaviour.** If the translator
   cannot read something, it names the construct, the file, the member and the
   line, and refuses that member. It does not emit something approximate.
2. **No source-specific hacks.** A fix that names one source is not a fix. If a
   construct recurs, support the construct.
3. **No knowingly incorrect semantics.** Kotlin's `replace` replaces all;
   `substringAfter` returns the whole string when the delimiter is absent; `+=`
   on a `val` collection mutates. Where the JavaScript differs, the runtime
   reproduces the Kotlin.
4. **Every compatibility primitive gets a regression test**, and the test must
   be _shown_ to catch its bug — break the fix, watch it fail, restore it.
5. **Rule 9.** No content source, anywhere, ever. See `docs/security.md`.

## Running it

```sh
bun install
bun run test
bun run check
bun run lint
```

The runtime generator is pinned to one bun version, because bundler identifier
renaming is not stable across minors and the generated bytes must be:

```sh
plugin-bridge generate --check
```

An edit to `packages/runtime/src/shims/dom.ts` is not real until that is
regenerated and committed.

## Where things live

See `docs/architecture.md`. In short: `core` reads, `runtime` is what the
converted bundle is built from, `adapters` know one ecosystem each, `host` is
the only capability there is, `cli` is thin.

## Commit messages

Say what changed and why it was wrong before. The interesting part of almost
every fix here is the failure it prevents, and that belongs in the history.
